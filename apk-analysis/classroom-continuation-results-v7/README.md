# 续答结果显示修复 v7

基于「学生端课堂-3.2.1.0-分屏底栏恢复-v6.apk」。用户1701/1702截图中，续答页新增的蓝色“2”没有出现在“我的作答”中。旧HandwriteCloud成功回调只保存去重指纹、发送原课堂通知和恢复按钮，没有刷新或更新结果页。

## 修改后的行为

- 手写续答通过原replyAsk接口回调成功后，保存本次上传的不可变笔迹快照。“我的作答”复用原结果控件、题目背景和笔迹解析流程显示该快照；上传期间又写、但尚未上传的内容不混入结果。
- 同时调用结果Fragment原refreshData，重新读取课堂结果。若返回笔迹与本次上传相同，直接显示服务器返回的原结果对象及其批阅信息。
- 如果原结果仍旧，先显示本次已被接口接受的笔迹，时间处标记“本次续答已上传 · 实际作答时长”。这是本次请求的显示版本，不冒充服务器回读、重新批阅、展优或新成绩；投影版本不沿用旧笔迹上的批阅和展优标记，原结果对象和共享LiveData保持原样。
- “展优作答”全部走原逻辑。正在查看该页时，上传成功也不强制切回“我的作答”。重新打开结果页、结果页迟到或重建时，仍使用同一份已上传版本，并重新读取原结果接口。
- 失败、异常和45秒超时保留上一次成功显示版本。换账号、题目、课堂或销毁续答页后，过期回调不能更新结果。MQTT通知失败与上传接口接受相互区分，结果读取失败也不会把已接受的上传改成失败或导致重复提交。
- 单选/多选续答上传成功后，同样触发原结果详情及统计刷新；**选择题仅显示原接口回读结果，不在本地重新计算判分或覆盖结果列表**。

结果控件原实现会把绘制放进View队列，并等待题图加载。新增每次更新的代次标记，使旧绘制任务、旧图片完成后的笔迹回调及其最后一次post不能覆盖新结果或另一个标签。保留原图片加载和笔迹绘制实现；没有改变笔迹坐标或缩放。

## 安装与检查

成品为「学生端课堂-3.2.1.0-续答结果显示修复-v7.apk」，原包名com.hljzjx.edu.student.classroom、版本3.2.1.0/321000、min29/target30以及classroom-mod签名证书保持。

在平板中进入结束后的手写题，继续写一个新标记，点击“上传续答”。接口接受后，打开“答题结果 → 我的作答”，应看到刚上传的标记；再写一个标记但不上传时，结果仍应显示上一份上传版本。时间处的“本次续答已上传”表示请求已被接口接受，不能作为老师端收到或后台已覆盖原记录的证明。

**本轮没有Pixel Tablet、真实课件或学校服务器联调。** 没有安装、卸载、清数据或发送真实HTTP/MQTT。后台是否允许结束后覆盖原作答，仍需实际结果回读和老师端验收；本补丁没有虚构新的更新接口。
